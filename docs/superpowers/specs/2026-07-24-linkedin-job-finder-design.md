# سند طراحی: سرویس پیداکردن جاب‌های لینکدین و ارسال به تلگرام

تاریخ: ۲۰۲۶-۰۷-۲۴

## هدف

سرویسی که هر روز به‌صورت خودکار جاب‌های مرتبط با برنامه‌نویسی (بیشتر خارج از ایران) را
پیدا می‌کند و برای هر جاب جدید یک پیام فارسی به یک کانال تلگرام می‌فرستد.

## تصمیم‌های کلیدی

| موضوع | تصمیم |
|-------|-------|
| زبان برنامه‌نویسی | Go |
| منبع داده | JSearch API روی RapidAPI |
| محل اجرا | GitHub Actions (زمان‌بندی روزانه، رایگان) |
| ضدتکرار | فایل `data/seen_jobs.json` که بعد هر اجرا داخل مخزن ذخیره می‌شود |
| خلاصه فارسی | فاز ۱ بدون AI (توضیح کوتاه از دیسکریپشن)؛ فاز ۲ با Claude API |
| هدف جاب‌ها | همه‌ی عنوان‌های مرتبط با برنامه‌نویسی، محل کار بین‌المللی |

## چرا این تصمیم‌ها

- **JSearch به جای اسکرپ مستقیم لینکدین:** اسکرپ مستقیم خلاف قوانین لینکدین است،
  سریع بلاک می‌شود و نگهداری مداوم می‌خواهد. JSearch جاب‌های لینکدین و بردهای دیگر را
  جمع می‌کند، قانونی است و پایدار.
- **GitHub Actions:** اجرای روزانه بدون نیاز به روشن‌بودن کامپیوتر شخصی، رایگان.
- **Go:** باینری تکی، پایدار، کتابخانه استاندارد برای HTTP و JSON کافی است و تقریباً
  بدون وابستگی خارجی کار می‌کند.
- **فقط جاب‌های جدید:** کانال اسپم نمی‌شود؛ هر جاب فقط یک‌بار ارسال می‌شود.

## معماری و اجزا

```
job-finder/
├── cmd/
│   └── jobfinder/
│       └── main.go            # نقطه شروع، هماهنگ‌کننده اصلی
├── internal/
│   ├── config/config.go      # کلمات کلیدی، فیلترها، خواندن متغیرهای محیطی
│   ├── jsearch/jsearch.go    # گرفتن جاب‌ها از JSearch
│   ├── store/store.go        # نگهداری آیدی جاب‌های دیده‌شده (ضدتکرار)
│   ├── message/message.go    # ساخت متن پیام فارسی
│   ├── summarize/summarize.go# فاز ۱ توضیح ساده، بعداً Claude API
│   └── telegram/telegram.go  # ارسال به کانال تلگرام
├── data/
│   └── seen_jobs.json        # آیدی جاب‌های ارسال‌شده
├── .github/workflows/
│   └── daily.yml             # زمان‌بندی روزانه
├── go.mod
├── .env.example
└── README.md
```

### مسئولیت هر واحد

- **config:** لیست کلمات کلیدی جست‌وجو، فیلترها (تاریخ انتشار، دورکاری)، سقف روزانه،
  فاصله بین پیام‌ها، و خواندن توکن‌ها از متغیرهای محیطی. ورودی: متغیرهای محیطی.
  خروجی: یک ساختار پیکربندی.
- **jsearch:** برای هر کلمه کلیدی به JSearch درخواست می‌زند، صفحه‌بندی را مدیریت می‌کند،
  و لیستی از جاب‌های نرمال‌شده برمی‌گرداند. وابستگی: کلید API، `net/http`.
- **store:** فایل `seen_jobs.json` را می‌خواند، جاب‌های جدید را فیلتر می‌کند، و آیدی‌های
  جدید را ذخیره می‌کند. برای جلوگیری از رشد بی‌نهایت فایل، آیدی‌های قدیمی (مثلاً بیش از
  ۳۰ روز یا بیش از یک سقف تعداد) هرس می‌شوند.
- **message:** از روی یک جاب، متن پیام فارسی تلگرام را می‌سازد (عنوان، شرکت، محل،
  توضیح کوتاه، لینک، تاریخ). وابستگی: ماژول summarize.
- **summarize:** فاز ۱ فقط چند جمله اول دیسکریپشن را تمیز و کوتاه می‌کند. رابط (interface)
  طوری طراحی می‌شود که در فاز ۲ بتوان پیاده‌سازی مبتنی بر Claude API را جایگزین کرد.
- **telegram:** پیام را با متد `sendMessage` بات به کانال می‌فرستد، با فاصله زمانی بین
  پیام‌ها و مدیریت خطای محدودیت نرخ. وابستگی: توکن بات، آیدی کانال.
- **main:** همه را به هم وصل می‌کند: پیکربندی → گرفتن جاب → فیلتر جدیدها → ساخت پیام →
  ارسال → ذخیره وضعیت.

## جریان کار روزانه

۱. GitHub Actions طبق زمان‌بندی cron بیدار می‌شود.
۲. برای هر کلمه کلیدی، جاب‌های «امروز» از JSearch گرفته می‌شوند.
۳. جاب‌ها با `seen_jobs.json` مقایسه می‌شوند؛ فقط جاب‌های جدید نگه داشته می‌شوند.
۴. برای هر جاب جدید یک پیام فارسی ساخته می‌شود.
۵. پیام‌ها با فاصله چندثانیه‌ای (و سقف روزانه) به کانال فرستاده می‌شوند.
۶. آیدی جاب‌های ارسال‌شده به `seen_jobs.json` اضافه و داخل مخزن commit می‌شوند.

## مدیریت خطا و محدودیت‌ها

- **محدودیت JSearch:** پلن رایگان درخواست کمی دارد (حدود ۶ درخواست در روز). تعداد کلمات
  کلیدی و صفحه‌ها قابل‌تنظیم و کنترل‌شده است. برای حجم بالاتر، پلن ارزان RapidAPI لازم است.
- **محدودیت تلگرام:** فاصله زمانی بین پیام‌ها و سقف روزانه قابل‌تنظیم، برای جلوگیری از فلود
  و خطای ۴۲۹ (Too Many Requests).
- **خطای شبکه/API:** هر خطا لاگ می‌شود و سرویس ادامه می‌دهد؛ یک اجرای خراب کل کار را
  متوقف نمی‌کند. آیدی جاب فقط وقتی «دیده‌شده» ثبت می‌شود که پیامش با موفقیت ارسال شده باشد.
- **امنیت:** توکن بات، آیدی کانال و کلید API فقط در GitHub Secrets و فایل محلی `.env`
  نگهداری می‌شوند و هرگز داخل کد یا مخزن قرار نمی‌گیرند.

## آزمایش (Testing)

- **store:** تست واحد برای فیلترکردن جاب‌های جدید و هرس آیدی‌های قدیمی.
- **message:** تست واحد برای ساخت درست متن پیام از یک جاب نمونه.
- **jsearch و telegram:** تست با پاسخ‌های HTTP جعلی (mock) بدون تماس واقعی با شبکه.
- **summarize:** تست واحد برای کوتاه‌سازی درست متن.

## پیش‌نیازهای کاربر (بعد از تأیید طراحی)

۱. اکانت RapidAPI و کلید API برای JSearch.
۲. بات تلگرام از BotFather و یک کانال (بات باید ادمین کانال باشد).
۳. مخزن گیت‌هاب برای کد و اجرای Actions، و ثبت توکن‌ها در Secrets.

## فازبندی

- **فاز ۱ (این سند):** گرفتن جاب، ضدتکرار، پیام با توضیح کوتاه، ارسال روزانه، اجرای خودکار.
- **فاز ۲ (بعداً):** خلاصه فارسی باکیفیت با Claude API و فیلترهای دقیق‌تر (سطح تجربه، حقوق،
  کشور خاص).

## خارج از محدوده (Out of Scope)

- اسکرپ مستقیم لینکدین.
- درخواست خودکار (اپلای) به جاب‌ها.
- رابط کاربری وب یا داشبورد.
- ذخیره‌سازی در پایگاه‌داده (فعلاً فایل JSON کافی است).
